# Class 3 - RAG & Memory in AI Agents

## Overview
This class explored how AI agents access and utilize **external knowledge** through **Retrieval-Augmented Generation (RAG)** and memory systems — allowing agents to go beyond what they were trained on.

## What is RAG?

**RAG (Retrieval-Augmented Generation)** is a technique that combines **information retrieval** with **language generation**.

Instead of relying only on pre-trained knowledge, RAG allows an AI agent to:
1. Fetch relevant information from external data sources in real-time
2. Use that retrieved data to generate accurate, context-aware responses

This makes agents more reliable and up-to-date, since they aren't limited to what they "memorized" during training.

## Data Vectorization

AI agents can't directly read raw files like PDFs or Word documents. To make content usable, it must be transformed into **vectors** — numerical representations that capture the meaning and context of the content.

- Vectorization allows the AI to **compare, search, and retrieve** relevant information efficiently.
- This is the foundation that makes RAG possible — without vectorization, there's no way for an AI to "search by meaning" instead of just by exact keyword match.

## How RAG Pipelines Work

A RAG pipeline generally follows 3 steps:

1. **Retrieve** — Search a knowledge base (vector database) for the most relevant chunks of information related to the query.
2. **Rank** — Sort the retrieved results by relevance, so the most useful context is prioritized.
3. **Generate** — Feed the top-ranked information into the LLM, which then generates a response using that real context.

## Vector Databases

Since RAG relies on searching large amounts of semantic (meaning-based) data, this data needs to be stored in a **vector database** — a database optimized for storing and querying vectors rather than plain text or numbers.

**Examples of vector databases:**
- **Pinecone**
- **Weaviate**
- **ChromaDB**

These allow fast similarity search — finding the pieces of data whose *meaning* is closest to the query, not just exact text matches.

## Embeddings

**Embeddings** are the actual numerical vector representations of text/data, generated by an embedding model. This is the practical mechanism behind vectorization — text goes in, a vector (list of numbers) comes out, and that vector captures the semantic meaning of the content.

## Tools for Connecting External Data to AI

- **APIs to vector databases** — e.g., Pinecone, Weaviate, ChromaDB, used to store and query embeddings.
- **Data ingestion pipelines** — e.g., **LangChain**, **LlamaIndex**, used to automate the process of loading, chunking, embedding, and storing external data.
- **Custom knowledge base integration** — connecting an agent to a company's or individual's own private data sources for enterprise-level or personalized solutions.

## Key Takeaway

RAG and vectorization demystify how AI agents extend beyond their training data. By retrieving relevant external content in real-time, agents become:
- More **reliable** (grounded in real, current data)
- More **dynamic** (can work with any external knowledge base)
- More **memory-aware** (can reference specific documents/data sources rather than relying purely on general trained knowledge)
